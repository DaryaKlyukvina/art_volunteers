# ArtVolunteers — сервис поиска волонтёров для арт-мероприятий

## Назначение
Консольное (в перспективе — веб-) приложение, которое соединяет организаторов
арт-мероприятий (арт-маркетов, ярмарок мастеров, выставок) с волонтёрами,
готовыми помочь в их проведении: встреча гостей, помощь мастерам,
логистика, фотосъёмка и т.д.

## Целевая аудитория
- организаторы арт-маркетов и ярмарок, которым нужны волонтёры на мероприятие;
- волонтёры, которые хотят участвовать в проведении творческих событий и
  выбирают мероприятия по дате, месту и нужным навыкам.

## Предметная область
Сервис хранит информацию об организациях-организаторах, мероприятиях, которые
они проводят, волонтёрах и их регистрациях на конкретные мероприятия.
Для каждого мероприятия известно, сколько волонтёров требуется, и сервис
не допускает регистрацию сверх этого количества или повторную регистрацию
одного волонтёра на одно и то же мероприятие.

## Основные сущности

- **Организация (организатор)** — организация или частное лицо, проводящее
  арт-мероприятие (поля: `id`, `name`, `contact`). Используется, чтобы связать
  мероприятие с тем, кто его организует: `id` организации хранится в поле
  `organization_id` у каждого мероприятия. Работа с сущностью реализована в
  модуле `organizations.py` — функции `add_organization()` (добавление новой
  организации) и `find_organization()` (поиск по подстроке названия).

- **Мероприятие** — арт-маркет, ярмарка и т.п. (поля: `id`, `title`,
  `organization_id`, `date`, `location`, `volunteers_needed`). Центральная
  сущность проекта: именно к мероприятию привязываются регистрации волонтёров
  и от него зависит, сколько ещё людей можно набрать. Реализована в модуле
  `events.py` — функции `add_event()` (добавление мероприятия),
  `find_event()` (поиск по названию), `filter_events_by_date()` (отбор
  мероприятий на конкретную дату) и `sort_events_by_date()` (сортировка списка
  мероприятий по дате для вывода в меню).

- **Пользователь (волонтёр)** — человек, готовый помогать на мероприятиях
  (поля: `id`, `name`, `contact`, `skills`). Используется, чтобы подбирать
  волонтёров под конкретное мероприятие по навыкам и регистрировать их на
  события. Реализована в модуле `volunteers.py` — функции `add_volunteer()`
  (добавление волонтёра) и `find_volunteers_by_skill()` (поиск волонтёров,
  владеющих нужным навыком).

- **Регистрация** — связь волонтёра с конкретным мероприятием (поля: `id`,
  `event_id`, `volunteer_id`). Отдельная сущность, а не просто отметка внутри
  Мероприятия или Волонтёра, потому что у одного мероприятия — много
  волонтёров, а один волонтёр может быть записан на несколько мероприятий
  (связь «многие ко многим»). Реализована в модуле `registrations.py` —
  функции `free_slots()` (сколько мест ещё свободно), `is_registration_possible()`
  (можно ли зарегистрировать волонтёра), `create_registration()` (создать
  регистрацию), `cancel_registration()` (отменить регистрацию по её `id`) и
  `get_registration_status()` (текстовое описание статуса для пользователя).

## Основные функции

- `organizations.add_organization()`, `organizations.find_organization()` —
  добавление и поиск организаций;
- `events.add_event()`, `events.find_event()` — добавление и поиск мероприятий;
- `volunteers.add_volunteer()` — добавление волонтёра;
- `events.sort_events_by_date()` — просмотр списка мероприятий, отсортированного
  по дате;
- `events.filter_events_by_date()` — отбор мероприятий по дате;
- `volunteers.find_volunteers_by_skill()` — отбор волонтёров по навыку;
- `registrations.free_slots()` — проверка количества свободных мест волонтёров
  на мероприятии;
- `registrations.create_registration()`, `registrations.cancel_registration()` —
  регистрация волонтёра на мероприятие и отмена регистрации;
- `storage.load_list()`, `storage.save_list()`, `storage.load_dict()`,
  `storage.save_dict()` — сохранение и загрузка всех данных в JSON-файлах.

## Формат хранения данных
Все данные хранятся в формате JSON в каталоге `data/`. Организации, мероприятия
и волонтёры хранятся как списки словарей с полем `id`; при загрузке в программе
они превращаются в словари `{id: запись}` для быстрого поиска. Регистрации
хранятся как список словарей `{id, event_id, volunteer_id}`.

## План развития
- ПР3 — сущности переработаны в классы (Event, User, Organization,
  Registration), инкапсуляция и наследование;
- ПР5–ПР6 — веб-приложение на Django, отображение мероприятий на страницах;
- ПР7, ПР9 — модели Django, база данных, ORM, админ-зона;
- ПР10 — формы регистрации на мероприятие и создания мероприятия;
- ПР11 — регистрация/аутентификация пользователей, разделение ролей
  «волонтёр» и «организатор»;
- ПР13–ПР15 — автоматизированное тестирование Django-приложения;
- в дальнейшем — REST API и развёртывание в Docker.
