# ArtVolunteers — платформа волонтёров для арт-мероприятий

## О проекте
Django-сайт, который помогает посетителям находить актуальные арт-мероприятия,
переходить на внешние сервисы покупки билетов и подавать заявки на волонтёрство.
Организаторы рассматривают заявки и принимают или отклоняют кандидатов.

## Технологии
- Python 3.11+
- Django 5.2+ (проверено на Django 6.0)
- SQLite (`db.sqlite3`), доступ к данным только через Django ORM
- Pillow — изображения мероприятий и логотипы организаций
- pytest, pytest-django, flake8

## Роли
- **Гость:** ищет и фильтрует опубликованные будущие мероприятия, смотрит страницы организаций и статистику.
- **Пользователь/волонтёр:** регистрируется, отправляет одну заявку на мероприятие, видит её статус.
- **Сотрудник организации:** создаёт, редактирует и отменяет мероприятия своей организации на сайте,
  видит заявки только своей организации, фильтрует их, принимает или отклоняет.
- **Администратор сайта:** управляет всеми данными через Django Admin.

## Страницы
| Адрес | Назначение |
|---|---|
| `/` | Каталог: поиск, фильтры по категории, организации и датам, «только со свободными местами», сортировка, пагинация |
| `/events/<slug>/` | Мероприятие по латинскому slug (например `/events/noch-v-galeree/`): описание, организация, свободные места |
| `/statistics/` | Статистика: заявки по статусам, категории, организации |
| `/organizations/<id>/` | Организация и её предстоящие мероприятия |
| `/applications/event/<id>/apply/` | Форма заявки волонтёра (нужен вход) |
| `/applications/mine/` | Мои заявки |
| `/applications/organization/` | Заявки организации: фильтры, сортировка, пагинация, принятие/отклонение |
| `/manage/events/` | Мероприятия организации (для сотрудников): изменение и отмена |
| `/manage/events/new/` | Создание мероприятия через форму |
| `/manage/events/<id>/edit/` | Редактирование мероприятия |
| `/manage/events/<id>/cancel/` | Отмена мероприятия (только POST) |
| `/accounts/signup/`, `/accounts/login/` | Регистрация и вход |
| `/admin/` | Административная панель |

## Модели данных
- `User` — встроенная модель Django.
- `Organization` — организатор (название, описание, контакт, сайт, логотип).
- `OrganizationMember` — сотрудник организации: `ForeignKey` на `Organization` и `User`, уникальная пара.
- `Category` — категория мероприятий (`slug` уникален).
- `Event` — мероприятие: `ForeignKey` на `Organization` (`on_delete=PROTECT`, `related_name="events"`)
  и `Category` (`SET_NULL`), латинский `slug` (уникальный, формируется из названия), дата, место,
  `volunteers_needed`, ссылка на билеты, изображение, статус `draft` / `published` / `completed` / `cancelled`,
  вычисляемое базой поле `is_large` (`GeneratedField`: нужно 10 и более волонтёров).
  Менеджер `EventQuerySet`: `published()`, `upcoming()`, `active()`, `for_date()`, `catalog()`, `with_free_slots()`.
  `get_absolute_url()` возвращает адрес страницы мероприятия, `cancel()` отменяет мероприятие без удаления.
- `VolunteerApplication` — заявка: `ForeignKey` на `User` и `Event` (`CASCADE`,
  `related_name="volunteer_applications"` / `"applications"`), контакты, опыт,
  статус `pending` / `accepted` / `rejected`. Менеджер `VolunteerApplicationQuerySet`:
  `pending()`, `accepted()`, `rejected()`, `for_event()`, `for_organizations()`, `with_related()`.

Правила предметной области:
- повторная заявка одного пользователя на одно мероприятие запрещена ограничением БД `unique_user_event_application`;
- число принятых заявок не может превышать `volunteers_needed` (`applications/services.py`);
- свободные места считаются только по **принятым** заявкам: отклонённые и ожидающие место не занимают.

ORM-запросы проекта перечислены в [docs/ORM_QUERIES.md](docs/ORM_QUERIES.md).

## Формы (Django Forms)
- `EventFilterForm` (`events/forms.py`, `forms.Form`) — фильтр каталога через GET-параметры: поиск,
  категория и организация (`ModelChoiceField`), даты (`DateField`), сортировка (`ChoiceField`),
  флажок «только со свободными местами». Проверки: `clean_q()` (не меньше 2 символов),
  `clean()` (дата «с» не позже даты «по» — общая ошибка формы). Ошибочное поле не применяется,
  остальные фильтры продолжают работать.
- `EventForm` (`events/forms.py`, `ModelForm`) — создание и редактирование мероприятия сотрудником
  организации. Пользователю доступны только поля организации (из своих), названия, категории, даты,
  места, числа волонтёров, ссылки на билеты, статуса (черновик/опубликовано), описания и изображения;
  `slug`, `created_at` и `is_large` формируются автоматически. Проверки:
  валидатор-функция `validate_has_letters` (название не из одних цифр), `validate_image_size` (до 3 МБ),
  `clean_date()` (не в прошлом), `clean_volunteers_needed()` (не меньше уже принятых),
  `clean()` — площадка занята, если на ней в тот же день есть другое **неотменённое** мероприятие;
  при редактировании текущее мероприятие исключается из проверки (`exclude(pk=...)`).
- Отмена мероприятия — только POST-запросом с `{% csrf_token %}`; статус меняется на «Отменено»,
  запись не удаляется, площадка освобождается. GET-запрос к адресу отмены возвращает 405.
- `VolunteerApplicationForm` (`applications/forms.py`, `ModelForm`) — заявка волонтёра, `clean_contact()`.
- Все формы оформлены классами Bootstrap (`BootstrapFormMixin`); Bootstrap 5 хранится локально в
  `static/vendor/bootstrap/`, поэтому сайт выглядит одинаково и без доступа к интернету.

## Изображения
Изображения мероприятий и логотипы организаций загружаются через формы сайта и административную
панель (`ImageField`, нужен Pillow), сохраняются в `media/` (`MEDIA_ROOT`) и раздаются по адресу
`/media/...` в режиме разработки (`config/urls.py`). Каталог `media/` не хранится в репозитории.

## Административная панель
`/admin/` — вход под суперпользователем (`python manage.py createsuperuser`).
- **Мероприятия:** столбцы с числом принятых заявок и признаком «Крупное», поиск по названию, описанию, месту
  и организации, фильтры по статусу, размеру, категории, организации и дате, редактирование статуса
  и числа волонтёров прямо в списке, действия «Опубликовать» / «Отменить», заявки в карточке (inline),
  ссылка «Смотреть на сайте» (через `get_absolute_url()`).
- **Заявки волонтёров:** поиск по имени, контакту, пользователю и мероприятию, фильтры по статусу, дате,
  организации, действия «Принять» (с проверкой свободных мест) и «Отклонить».
- **Пользователи:** в карточке — заявки пользователя и его организации.
- **Организации:** число мероприятий, сотрудники и мероприятия в карточке.
- **Категории:** число мероприятий в каждой категории.

## Инструменты разработки
- Контекстный процессор `events.context_processors.site_context` передаёт во все шаблоны
  название сайта и число предстоящих мероприятий (выводится в меню).
- Django Debug Toolbar подключается автоматически при `DEBUG = True`, если установлен пакет
  `django-debug-toolbar` (входит в `requirements.txt`); при запуске тестов отключается.
  Панель SQL показывает выполненные запросы и время их выполнения.

## Установка и запуск
```bash
git clone https://github.com/DaryaKlyukvina/art_volunteers.git
cd art_volunteers
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
python manage.py seed_demo
python manage.py runserver
```
Откройте `http://127.0.0.1:8000/`. Админ-панель: `http://127.0.0.1:8000/admin/`.

## Наполнение базы данных
База `db.sqlite3` не хранится в репозитории: таблицы создаются миграциями.
- `python manage.py seed_demo` — демонстрационные организации, категории, 15 мероприятий,
  6 волонтёров и организатор `organizer` (пароль всех демо-пользователей `DemoPass123!`).
  Повторный запуск не создаёт дублей, `--reset` пересоздаёт мероприятия и заявки.
- `python manage.py import_legacy_json --directory data` — перенос организаций и мероприятий
  из JSON-файлов прежней консольной версии.

## Структура
- `config/` — настройки проекта Django.
- `accounts/` — регистрация, вход и личный кабинет.
- `organizations/` — организации, сотрудники, команды `seed_demo` и `import_legacy_json`.
- `events/` — категории, мероприятия, каталог и статистика.
- `applications/` — заявки волонтёров, их статусы и кабинет организатора.
- `templates/` — HTML-шаблоны; `docs/` — документация.
- `media/` — загружаемые изображения (не хранится в репозитории).

Старые консольные модули (`main.py`, `storage.py`, `legacy_events.py`,
`legacy_organizations.py` и др.) оставлены как история первых практических работ.
